# ADR: 不要收藏夹——星级轴已经承载了它

> **Languages:** [English](ADR-no-favorites.md)（主文档） · [中文](ADR-no-favorites.zh-CN.md)

日期：2026-10-21　状态：**Accepted**（裁决；无代码改动——它指向的数据模型已实现）

**取代**：`docs/EXTENSIONS.md` 中 launcher 时代草案的那一条——把「星级 / 收藏」
列为 mudra 还需补建的数据能力（`site_stars` 或 state 位）。那份草案已作废，
本 ADR 关闭它提议的这条路。

## 问题

浏览器需要一种"把这一页留着"的表达。通常的答案是收藏夹 / 书签列表：一个页面级的
成员位，配自己的存储、动词与 UI。mudra 需要这样一个东西吗？

## 决定

不要。mudra 不设收藏夹，不设 `star` / `unstar` 动词，也不为它预留 collection。

收藏夹是**一个成员位**。而人真正"存下"一页时表达的是 mudra 已经用 tag 树维护的
那组轴之一、或几条轴的组合——**importance ★ / quality ♥ / urgency 🔥**，以及未来
新维度各自成轴。这个位是该空间在单一维度上的投影，所以**粒度太粗**：三条轴各五档
是 125 个状态，成员位把它们全都叫作"已收藏"。

丢掉的不是装饰性信息，而是**为什么留下**：

- importance ★5——"什么时候都可以再读一遍"
- quality ♥5——"好资料，但不紧张"
- urgency 🔥4——"一周内要动手"

三者在收藏夹里长成同一行；列表也无法在读取时区分"现在该读什么"（urgency）与
"以后该引什么"（quality），除非人再手判一次理由。

机制已经在了：`rank` 是 **Tag** 上的字段，一条 rank 轴 = 一棵子节点各带 `rank` 1..5
（0 = 不是 rank 子节点，也是面板 k=0「清掉这条轴」的语义）的 tag 树，页面的档位
**就是**它携带的那条 tag 边（`docs/SCHEMA.md`：Tag ns 1、`page_tag` 双写 junction）。
存储还种了一条非 rank 的兄弟维度——`state` 流水线（to-read / reading / distilled /
archived），收藏位会同它的 "to-read" 争同一个问题。写面也有：`/set_tags`、
`/tag_set`、面板的评分 pip（`set_rank`）。所以收藏夹只会是同一存储里第二份、更粗的
副本——正是 tag 森林当年替掉 session 时所否掉的那种失效形态。

## 后果

- "已收藏的页"的读取面是 `page_tag` 的 tag→page 方向，不是收藏表：「importance ≥ 4
  的页」是对既有边的一次查询。想要这种 picker 的调用方——例如 `:open` 的第三候选源
  （现为活页 + 打开历史）——读的就是这个方向。
- 真正不属于这三条轴的维度，形态是**新开一条 rank 轴**，不是成员位。词汇只有一套，
  靠加树扩展。
- 文件夹唯一独有的东西——人手工排的次序——是 rank 与时间的**视图**，不是存储状态；
  不新增次序字段。
- 控制面不增长：不加 `/star`，不改 schema，`/open` / `/pages` 维持原样。

## Why not

- **专门的 collection（`site_stars`、`pinned` 位、`/star` 动词）**——按上面的粒度
  论证否掉：它把轴复制成一位的分辨率，而且正是已作废的 launcher 草案所提的路径。
- **plain tag `starred`**——比 collection 便宜，但同样是塌缩：它在轴旁边立起第二个
  "重要"概念；且没有档位，能说"收藏了"，永远说不出"多重、为什么"。
- **只存在面板侧的应用列表**——同一个问题两处真相；面板还得分头与它已在写的轴对齐。
